[권장 기술 구성]

- 코드 편집: VS Code, Cursor(AI)

- 계산 검증: Excel
- 구조도: draw.io

2단계. 시스템 전체 구조 설계
============================================================

목적
3D 화면, 계산 엔진, 교육/평가, DB를 서로 분리합니다.

권장 구조

[3D 웹 화면]
      ↓
[설비 상태/조작 데이터]
      ↓
[Simulation Engine]
      ↓
[Training / Evaluation]
      ↓
[Database]

핵심 원칙
- 3D 모델은 계산하지 않습니다.
- 계산 엔진은 화면을 몰라도 작동해야 합니다.
- 교육 시나리오는 3D 모델과 분리합니다.

예: 밸브 개도 70%라는 상태를 계산 엔진에 전달하면 계산 엔진이 유량/압력을 계산하고 3D 화면은 결과를 표시합니다.

완료 기준
각 기능이 어느 모듈에 들어가는지 결정되어 있어야 합니다.

AI 활용
시스템 아키텍처, 클래스 관계, 데이터 흐름을 ChatGPT로 검토합니다.

============================================================
4단계. 계산 엔진 개발
============================================================

가장 중요한 단계입니다. 3D 모델보다 먼저 개발합니다.

목적
펌프와 배관 시스템의 상태가 변할 때 유량, 압력, 유속 등이 어떻게 변하는지 계산하는 핵심 프로그램을 만듭니다.

주요 객체 예
Pump
Pipe
Valve
PressureGauge
FlowMeter
System

처음에는 3D가 없어도 됩니다. C# 콘솔 프로그램으로 계산 결과를 출력해도 됩니다.

중요
계산식은 실제 설비 기준, 관련 기준/교육자료 및 검증 가능한 기술자료를 바탕으로 정해야 합니다. AI가 임의로 만든 물리식을 그대로 사용하지 않습니다.

완료 기준
동일한 입력에 일관된 결과가 나오고 시험 조건별 예상 결과와 비교하여 검증할 수 있어야 합니다.

AI 활용
- C# 클래스 작성
- 계산 로직 초안
- 단위 테스트
- 오류 검토
- 리팩터링
- 문서화

============================================================
5단계. 계산 엔진 검증
============================================================

목적
3D 화면을 만들기 전에 계산 결과가 맞는지 검증합니다.

방법
Excel 기준 계산표를 만들고 C# 계산 결과와 비교합니다.

예:
조건 A → Excel 결과 ↔ C# 결과
조건 B → Excel 결과 ↔ C# 결과
조건 C → Excel 결과 ↔ C# 결과

테스트
[ ] 펌프 OFF
[ ] 펌프 ON
[ ] 밸브 완전 개방
[ ] 밸브 부분 개방
[ ] 유량 변화
[ ] 압력 변화
[ ] 비정상 조건

완료 기준
3D 화면 없이도 계산 엔진의 결과를 신뢰할 수 있어야 합니다.

6단계. Blender로 3D 모델 제작
============================================================

계산 엔진의 기본 검증이 끝난 후 시작합니다.

우선 제작할 모델
1. 펌프
2. 밸브
3. 배관
4. 압력계
5. 유량계
6. 저수조
7. 시험배관

처음부터 실물 수준의 고해상도 모델을 만들지 않습니다. 교육용으로 알아보기 쉽고 웹에서 빠르게 움직이는 모델을 우선합니다.

AI 활용
Blender Python을 ChatGPT로 작성하여 반복적인 배관, 플랜지, 기본 형상 생성에 활용합니다.

완료 기준
전체 시험배관을 3D로 볼 수 있고 주요 부품을 각각 선택할 수 있어야 합니다.

8단계. 3D와 계산 엔진 연결
============================================================

제품다운 제품이 만들어지는 단계입니다.

동작 예

→ Valve.Opening
→ 계산 엔진 실행
→ Flow / Pressure / Velocity
→ 3D 계기판 표시

3D는 단순한 영상이 아니라 계산 결과를 실시간으로 보여주는 인터페이스가 됩니다.

완료 기준
밸브 조작에 따라 계산 결과와 화면의 계기값이 실제로 변해야 합니다.

AI 활용
API 구조, TypeScript 연결 코드, C# ASP.NET Core API, 오류 처리 코드를 단계별로 작성시키고 검토합니다.

AI를 최대한 활용하는 방법
============================================================

AI에게 한 번에 전체 프로그램을 만들게 하지 않습니다.

권장 순서
1. 설계
   "FP-01 계산 엔진의 C# 클래스 구조를 설계해줘."

2. 데이터 구조
   "Pump, Valve, Pipe 등의 관계와 속성을 설계해줘."

3. 코드
   "Pump 클래스를 C#으로 작성해줘."

4. 테스트
   "이 클래스의 단위 테스트를 작성해줘."

5. 검증
   "이 코드에서 논리 오류와 물리적으로 잘못될 가능성을 찾아줘."

6. API
   "ASP.NET Core API로 연결해줘."

7. 3D
   "Three.js에서 밸브 회전값과 Valve.Opening을 연결해줘."

8. Blender
   "배관과 플랜지를 생성하는 Blender Python 스크립트를 작성해줘."

9. 문서화
   "현재 코드의 구조와 각 클래스의 역할을 문서화해줘."

AI가 만든 코드는 반드시 직접 실행하고 테스트합니다.
특히 소방설비 계산식, 교육절차, 기준값은 AI 답변만으로 확정하지 않습니다.

============================================================
가장 중요한 원칙
============================================================

1. 코딩보다 요구사항을 먼저 확정한다.
2. 3D보다 계산 엔진을 먼저 만든다.
3. 계산 엔진은 독립적으로 테스트한다.
4. 3D 모델과 계산 엔진을 분리한다.
5. 교육 시나리오와 3D 모델도 분리한다.
6. AI에게 큰 프로그램 전체를 한 번에 만들게 하지 않는다.
7. AI에게 설계 → 코드 → 테스트 → 수정 순서로 작은 단위의 작업을 시킨다.
8. AI가 만든 소방설비 계산식은 반드시 사람이 검증한다.
9. 첫 목표는 완성품이 아니라 작동하는 FP-01 MVP다.
10. MVP 검증 후 다른 소방설비와 타 산업으로 확장한다.

============================================================
지금 바로 시작할 첫 작업
============================================================

사업계획서 다음에는 'FP-01 요구사항 정의'부터 시작합니다.

첫 작업에서 확정할 7가지
1. 어떤 소방펌프 시험을 교육 대상으로 할 것인가?
2. 어떤 설비를 3D로 표현할 것인가?
3. 교육생이 어떤 조작을 할 것인가?
4. 어떤 값을 계산할 것인가?
5. 어떤 시험 절차를 수행하게 할 것인가?
6. 무엇을 기준으로 채점할 것인가?
7. MVP에서는 어디까지 만들고 어디서 멈출 것인가?

이 7가지가 확정되면 실제 개발 프로젝트를 시작합니다.
